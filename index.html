How it works

Five ideas every production data pipeline uses.

1Orchestration

A cron schedule in GitHub Actions starts a clean machine every hour. No server stays on between runs.

2Data contract

Each API response is checked for the fields we depend on. If the provider changes its schema, the run fails loudly instead of silently corrupting data.

3Quality gate

Range, null, duplicate and freshness checks run before loading. A failed check stops the load, so bad data never enters history.

4Idempotent history

Hourly snapshots are appended and pruned to 7 days. Re-running the same hour replaces it instead of duplicating it.

5SQL analytics layer

Gold tables are built with SQL: point gain per story, keyword momentum against 6 hours earlier, topic share and source rankings.
